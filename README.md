# mca——从零实现的单机受控编程智能体

Git 仓库：https://github.com/chenzhan20050128/czCodeAgent

## 一、项目简介

mca 是一个不依赖任何 Agent 框架或 SDK 的命令行编程智能体，仅使用 Python 和 httpx，通过 OpenAI 兼容的 Chat Completions 协议调用模型。模型只负责生成文本和工具调用；文件操作、命令执行、权限审批、状态管理、错误处理与循环终止均由本地运行时实现。

## 二、核心机制

1. Rollout 是唯一事实源。用户输入、模型回复、审批决定、工具执行和 Turn 终态都按顺序写入 append-only JSONL，并通过 fsync 持久化。内存状态和模型上下文均由日志重新归约、投影生成，避免维护两套可能不一致的历史。

2. 本地状态机掌握控制权。系统不会只根据 finish_reason 判断完成：只要响应包含 tool_calls，就必须执行并回传结果；空响应、截断和协议错误均不能被当作成功。达到最大步骤后，仅允许一次不携带工具的收口采样，保证循环有界。

3. 副作用显式可控。工具调用依次经过参数校验、用户审批、文件快照、开始事件、实际执行和结果落盘。若程序在工具开始后崩溃，恢复时将结果标记为 outcome_unknown，要求用户核对，不会静默重试可能已经发生的操作。

## 三、主要功能

- 支持读取、搜索、创建和编辑文件，以及执行 Shell 命令；
- 文件路径限制在工作区内，拒绝路径穿越和符号链接逃逸；
- 文件修改展示 diff，并采用冲突检测和原子替换；
- Shell 命令具有超时、输出截断和进程组清理机制；
- 支持 Plan Mode、会话级审批、受管文件修改撤销；
- 支持上下文自动压缩，保留原始审计日志；
- 支持会话恢复、崩溃对账及只读会话回放；
- 使用自行实现的 SSE 解析器组装流式文本和工具调用。

## 四、安装与运行

```bash
python3 -m venv .venv
.venv/bin/pip install -e .
export MCA_API_KEY=你的密钥
mca "修复项目中失败的测试"
```

- 交互模式：`mca`
- 计划模式：`mca --plan`
- 恢复会话：`mca --resume <session-id>`
- 运行测试：`python3 -m unittest discover -s tests -v`

API Key 仅从环境变量读取，不写入仓库、日志或子进程环境。mca 不提供操作系统级沙箱，Shell 命令仍具有当前用户权限。
